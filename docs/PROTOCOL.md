# v2 协议

项目只实现这一种协议。默认分块 2100 字节，编码时可指定 1–2124 字节；分块大小随 START 传递。

## 线格式

```text
CONTENT_HEX + CONTENT_MD5_HEX + PACKET_ID_HEX
```

所有字符为大写 HEX。正文是原始字节的 HEX；MD5 是原始正文的 32 位大写摘要，不能再次 HEX 编码；编号先转成 8 位十进制 ASCII，再 HEX 编码成 16 字符。解析时从尾部拆分 16 字符编号、32 字符摘要和正文，验证长度、大小写、十进制编号及正文 MD5。

| 帧 | 编号 | 原始正文 |
|---|---|---|
| START | 88888888 | UTF-8：`文件名,文件MD5,总包数,分块字节数` |
| DATA | 00000000 起 | 原文件分块，末包保留实际长度 |
| FINISH | 99999999 | UTF-8：`finish` |

文件名可含逗号，START 从右侧拆分最后三个字段。文件 MD5 为实际传输文件的 32 位大写摘要；目录传输填写 ZIP 字节摘要。空文件总包数为 0，不产生 DATA。总包数最多 88888888。

非末包长度必须等于 START 分块大小；末包为 1 到该大小。DATA 编号必须落在 START 的总包数范围内。全局 DATA 上限 2124 字节，对应 QR 最大 4296 个字母数字字符（`2 × 2124 + 48`）；超限在编码时明确拒绝。

## 二维码与播放

二维码自动选择版本、纠错 L、四模块留白。使用大写 HEX 文本，使库选择字母数字模式；基础模块 10 像素，再以最近邻缩至 50%，最大二维码 925×925 像素。录屏必须覆盖完整留白。

默认每帧 50ms；播放和合成测试视频重复 START、FINISH 各 20 次，DATA 每包一次。PNG 导出每种控制帧只写一张。二维码生成速度和系统调度可能使实际播放间隔变长。

## 合并和完整性

START 的文件名、MD5、总包数、分块大小锁定任务。同编号同内容去重；不同内容隔离并阻止恢复。FINISH 只表示发送结束；START 已知、包完整、整体 MD5 一致才可以恢复，不要求必须收到 FINISH。

缺包清单保存原始编号，补传必须使用相同文件、分块大小、原编号和内容。多个视频必须明确属于同一文件；DATA 不包含文件 ID。恢复按编号流式写入临时文件，校验成功后原子发布，不覆盖已有用户文件。MD5 用于传输一致性校验，API 访问另用 Token。

目录使用确定性 ZIP，ZIP 的字节 MD5 与目录内容指纹分别校验；恢复 ZIP 不自动解压。历史协议实现和兼容分支已移除。
